# 引き継ぎ用の説明

README とコードを読み、作成者以外の人がこのツールを保守し始めるための説明を、次の形式で出す。

```
## このツールは何か(3行)

## 業務の流れの中での位置づけ
- 入力はどこから来て、出力は誰が何に使うか

## 処理の流れ
1. (関数名・ファイル名つきで)

## 改修するときに触る場所
- 判定ルールを変える → (ファイル名・関数名)
- 入力形式が変わった → (ファイル名・関数名)
- 設定値を変える → .env / (設定を読むファイル)

## このツール固有のルール・注意点
- README の「このツール固有のルール」「過去の障害・注意点」と、コードから読み取れるリスク

## README に書かれていない・分からなかったこと
- 作成者に確認すべき質問のリスト
```

最後の「分からなかったこと」は必ず出す。これは README の改善点でもあるので、
ユーザーが作成者から回答を得たら `/team:update-context` で README に反映するよう提案する。
