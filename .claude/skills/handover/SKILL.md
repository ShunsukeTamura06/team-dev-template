# 引き継ぎ用の説明

READMEとコードを読み、作成者以外の人がこのツールを保守し始めるための説明を、次の形式で出す。

```
## このツールは何か(3行)

## 業務の流れの中での位置づけ
- 入力はどこから来て、出力は誰が何に使うか

## 処理の流れ
1. (関数名・ファイル名つきで)

## 改修するときに触る場所
- 判定ルールを変える → app/logic.py の〇〇
- 入力形式が変わった → app/data_io.py の〇〇
- 設定値を変える → .env / app/config.py

## 注意点
- READMEの「過去の障害・注意点」と、コードから読み取れるリスク

## READMEに書かれていない・分からなかったこと
- 作成者に確認すべき質問のリスト
```

最後の「分からなかったこと」は必ず出す。これはREADMEの改善点でもあるので、
ユーザーが作成者から回答を得たら `/update-context` でREADMEに反映するよう提案する。
